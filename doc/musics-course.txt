musics.lang -- a little course
===============================

Starting it -- three ways, not interchangeable:

- `lein run` (or `lein run -m musics.lang`, identical now that
  `project.clj` names `musics.lang` as `:main`) drops you straight into
  musics-lang's own prompt (`musics-lang. Ctrl-D or \`bye\` to exit.
  >`) -- that's musics-lang's own reader, not a Clojure REPL, so a
  Clojure form like `(require ...)` typed there just gets fed to
  musics-lang's own tokenizer and fails. Real up/down-arrow history
  needs `lein trampoline run` specifically, not plain `lein run` --
  plain `lein run` launches java as a child process in a way that
  breaks terminal detection (`System.console()` comes back `nil`),
  confirmed live; the REPL still works fine either way, it just falls
  back to no history/line-editing under plain `lein run` -- it tells
  you so directly the moment that happens.
- `lein repl` starts an actual Clojure REPL -- THIS is where
  `(require '[musics.lang :as l])` belongs, and it's how every example
  below was actually run and verified, not guessed:

    $ lein repl
    user=> (require '[musics.lang :as l])
    user=> (def ctx (l/make-ctx))
    user=> (l/run-string ctx "3 4 + .s")

From inside that same Clojure REPL, `(l/repl!)` drops you into a nested
musics-lang prompt without leaving the Clojure session -- same effect
as `lein run -m musics.lang`, except `bye`/Ctrl-D returns to the
Clojure REPL instead of exiting the process.

Every prompt shown below is the REAL one, `vocab>` -- just the current
vocabulary's own name, recomputed fresh every line as `IN:` changes it
-- not a placeholder, and every line below was actually run to get it.
These transcripts call `run-string` directly the same way `(l/run-string
ctx ...)` above does, so they don't show the live interactive loop's own
`" ok<depth>"` trailer (`run-repl-loop`, printed after each line
actually runs, real Factor's own listener convention) -- that only
shows up when you're actually typing at a real `lein run`/`(l/repl!)`
prompt, not reading a transcript here.


1. The stack, and the prompt
-----------------------------

Everything is postfix: push values, then call a word that consumes
them:

    scratchpad> 3
    scratchpad> 4 +
    scratchpad> .
    7
    scratchpad>

`+` pops both `3`/`4`, pushes their sum; `.` pops and prints. At a real
interactive prompt (not this transcript style, see above) the line
`4 +` would print `ok<1>` right after it -- one item left on the stack
-- and `.` would print `ok<0>` right after popping it back off. `.s`
shows the whole stack without touching it (so its own depth stays the
same right after); `dup`/`swap`/`drop`/`over`/`rot`/`nip`/`pick`/
`2dup`/`clear` round out the shufflers:

    scratchpad> 5 dup *
    scratchpad> .
    25
    scratchpad>


2. Numbers
----------

    scratchpad> 1 3 / .
    1/3
    scratchpad> 0.25 .
    0.25
    scratchpad> 1 3 / 0.5 + .
    0.8333333333333333

`1 3 /` stays an exact ratio -- Clojure's own numeric tower, not a
hand-rolled one. Mix a ratio with a float and it promotes to float,
same as real Factor's own tower rule.

`mod`/`rem`/`floor`/`neg`/`abs`/`gcd` all behave exactly as Clojure's
own built-ins do -- a deliberate choice, NOT real Factor's own
convention (real Factor's own `mod` actually takes the sign of the
dividend, the opposite of Clojure's; "data types are Clojure's" here
extends to arithmetic behavior too):

    scratchpad> -7 2 mod .
    1
    scratchpad> -7 2 rem .
    -1

`mod` -- sign of the divisor. `rem` -- sign of the dividend, a
genuinely different word, not a synonym. `/mod` gives the truncated
quotient and remainder together, mutually consistent with each other
(`q*y + r = x` always -- this one leaves TWO values, hence depth 2):

    scratchpad> -7 2 /mod .s
    -3 -1
    scratchpad>

The rest of the toolkit: `neg`/`abs`, `gcd`, `floor`:

    scratchpad> -5 neg .
    5
    scratchpad> -5 abs .
    5
    scratchpad> 54 24 gcd .
    6
    scratchpad> 7 2 / floor .
    3

That's `+ - * / mod rem /mod neg abs gcd floor < > <= >= = not` --
`ceiling`/`truncate`/`round`/`zero?`/`even?`/`odd?`/`min`/`max` aren't
built yet.


3. Quotations -- the core idea
-------------------------------

A quotation is code you don't run yet, just hold as a value -- spelled
with Clojure's own list syntax, `( ... )`, not Factor's `[ ... ]` (a
deliberate choice for this kernel: everything else in section 5 IS
Clojure's own literal syntax, and a quotation is the one place that
syntax means "run me" instead of "I am data"):

    scratchpad> ( 1 + ) .
    ( 1 + )

(Quotations print back as their own real source, reconstructed from
what was actually typed -- not a placeholder. Same underlying idea as
real Factor's own printing philosophy: show almost any value as valid,
re-readable source.)

To actually run one:

    scratchpad> 5 ( 1 + ) call .
    6

This is THE replacement for if/loops as special syntax -- there's no
`if` keyword, just a word called `if` that takes a boolean and two
quotations:

    scratchpad> true ( "yes" ) ( "no" ) if .
    "yes"
    scratchpad> false ( "yes" ) ( "no" ) if .
    "no"

(Only `false` -- and Clojure's own `nil` -- are falsy; `0` and an
empty sequence are TRUE here, unlike classic Forth. `.` shows the
string WITH quotes -- see section 6, deliberate, not a stray artifact.)

`when`/`unless` are the one-branch versions:

    scratchpad> true ( "ran" ) when .
    "ran"

`?` is the TERNARY version -- picks between two plain VALUES, not
quotations, so nothing gets run or skipped, both sides are already on
the stack either way (real Factor's own kernel word, confirmed against
its own worked example):

    scratchpad> 3 4 < "less" "not less" ? .
    "less"


4. Combinators worth knowing early
-----------------------------------

    scratchpad> 5 ( 1 + ) keep .s
    6 5
    scratchpad>

`keep` runs the quotation on a value, then gives you the original back
too -- handy for "compute something but don't lose what you started
with" (two values left, hence depth 2).

    scratchpad> 5 ( 1 + ) ( 2 * ) bi .s
    6 10
    scratchpad>

`bi` applies two quotations to the SAME original value. `tri` is the
three-quotation version. `dip`/`2dip`/`3dip` run a quotation with the
top one/two/three items set aside, then restore them.


5. Sequences and data -- Clojure's own literal syntax
-------------------------------------------------------

No `<vector>`/`set-nth`-style constructor words here -- data types are
Clojure's own, and so is their syntax. Just write it:

    scratchpad> [1 2 3] .
    [1 2 3]
    scratchpad> {:a 1} .
    {:a 1}
    scratchpad> #{1 2 3} .
    #{1 3 2}

(A set's own printed element order isn't guaranteed -- it's still the
same set either way.) Nesting needs no special handling: `[1 [2 3]
{:a #{4 5}}]` reads back exactly as typed. A bare `:name` reads as a
real keyword too, the same way `{:a 1}` already has one inside it:

    scratchpad> :a .
    :a

`each`/`map`/`filter`/`reduce` are the sequence combinators, same
shape as section 4's own `keep`/`bi`:

    scratchpad> [1 2 3] ( 10 * ) each .s
    10 20 30
    scratchpad>
    scratchpad> [1 2 3] ( 2 * ) map .
    [2 4 6]
    scratchpad> [1 2 3] 0 ( + ) reduce .
    6

`nth`/`get`/`assoc`/`conj`/`first`/`rest`/`count` read a collection
apart or build one up, one piece at a time -- Clojure's own arg order
(collection first), not Factor's own collection-last convention:

    scratchpad> [1 2 3] 1 nth .
    2
    scratchpad> { :a 1 } :a get .
    1
    scratchpad> { :a 1 } :b 2 assoc .
    {:a 1, :b 2}
    scratchpad> [1 2] 3 conj .
    [1 2 3]
    scratchpad> [1 2 3] first .
    1
    scratchpad> [1 2 3] rest .
    [2 3]
    scratchpad> [1 2 3] count .
    3

TUPLE:/GENERIC:/M: (a small object system) aren't built.


6. Strings, and word references
----------------------------------

`.` always shows the full, valid-source form of whatever's on the
stack -- for a string, that means WITH quotes. `print` shows a
string's own RAW content instead, no quotes, no trailing newline
(chain `nl` on if you want one):

    scratchpad> "hi" .
    "hi"
    scratchpad> "hi" print
    hi

Word references use a backslash, real Factor's own syntax, not a
tick -- `execute` runs one:

    scratchpad> : inc 1 + ;
    scratchpad> 5 \ inc execute .
    6


7. Vocabularies -- keeping things separate
---------------------------------------------

Vocabulary words are the one family spelled UPPERCASE, real Factor's
own convention (ordinary words stay lowercase; a parsing word like
this is uppercase-with-colon) -- lowercase `in:`/`use:`/etc. are just
unknown words now, not aliases. Watch the prompt's own vocab name
change with `IN:` too:

    scratchpad> IN: my-shapes
    my-shapes> : double 2 * ;
    my-shapes> IN: scratchpad
    scratchpad> 5 double .
    Error: unknown word: double

That fails -- `double` isn't visible from `scratchpad` (the default
vocabulary this REPL starts in), even though the current PROMPT says
`scratchpad>` again by the time it's typed (the `5` that was pushed
before the error stays on the stack, for what it's worth -- errors
here don't roll anything back). Fix it with `USE:`:

    scratchpad> IN: my-shapes
    my-shapes> : double 2 * ;
    my-shapes> IN: scratchpad
    scratchpad> USE: my-shapes
    scratchpad> 5 double .
    10

`USING:` does several `USE:`s at once, ended by `;`. Finer-grained
imports exist too -- `FROM: vocab => word ... ;` (only these words,
winning over an ambiguous `USING:`), `EXCLUDE: vocab => word ... ;`
(everything but these), `RENAME: word vocab => new-name`, `QUALIFIED:
vocab`/`QUALIFIED-WITH: vocab prefix` (`vocab:word`/`prefix:word`
access), and `FORGET: word` (removes a word from the current
vocabulary). `vocabs`/`words`/`vocab` list what's around.

`USE:` is TRANSITIVE -- a vocab USEd by a vocab you use is visible too,
any number of levels deep (cycle-safe: a mutual `USE:` between two
vocabs resolves instead of hanging). This is exactly how this project's
own bundled `algo` vocab is organized: it `USE:`s 8 sibling vocabs
(`algo-common`/`algo-indisp`/`algo-melodic`/`algo-metric`/
`algo-random`/`algo-rhythmic`/`algo-algoline`/`algo-toolkit`, a
mechanical bridge of this project's whole `algo/` generative-algorithm
tree), and `scratchpad` only directly `USE:`s `{musics, parse, algo}`
-- yet every one of those 329 words is still reachable, nothing further
to wire up:

    scratchpad> [2 2 3] indispensability .
    [11 0 4 8 2 6 10 1 5 9 3 7]

`indispensability` lives in `algo-indisp`, two `USE:` hops from
`scratchpad` (through `algo`) -- `scratchpad` never mentions
`algo-indisp` by name at all.

A vocabulary can be CLOSEd against new or forgotten words -- reading it
(`USE:`/`QUALIFIED:`/a plain lookup) stays completely unaffected, only
`:`/`::`/`FORGET:` are blocked:

    scratchpad> IN: kernel : dup 99 ;
    Error: cannot define "dup" -- vocab "kernel" is closed (see OPEN:)

Every built-in vocabulary (`kernel`, `musics`, `parse`, `algo`, and all
8 `algo-*` ones) starts closed for exactly this reason -- `scratchpad`,
and any vocab you create yourself, start open. `OPEN: vocab-name`
reverses `CLOSE: vocab-name`.


8. Looking words up: see, stack-effect, word-doc, where
------------------------------------------------------------

Every word -- built-in or your own -- can be inspected the same way
real Factor lets you inspect one, via a word reference:

    scratchpad> : square ( x -- y ) dup * ;
    scratchpad> \ square see
    : square ( x -- y ) dup * ;
    scratchpad> \ square stack-effect .
    "( x -- y )"

Attach a one-line description with `HELP:` (uppercase, same parsing-
word family as section 7's own `IN:`/`USE:`), read it back with
`word-doc` (both show up together in `see`'s own output too):

    scratchpad> : square ( x -- y ) dup * ;
    scratchpad> HELP: square "squares a number"
    scratchpad> \ square see
    square -- squares a number
    : square ( x -- y ) dup * ;

`\ word where` reports which vocabulary a word lives in:

    scratchpad> \ dup where .
    "kernel"


9. Variables and constants
------------------------------

`VARIABLE: name` interns a real Clojure Var and defines `name` as a
word that pushes the VAR ITSELF -- its identity, not its current value
(the same convention real Factor's own `SYMBOL:` uses). `@` (fetch) and
`!` (store) read and write it:

    scratchpad> VARIABLE: hits
    scratchpad> hits @ .
    nil
    scratchpad> 1 hits ! hits @ 1 + hits ! hits @ .
    2

`CONSTANT: name value` is real Factor's own syntax exactly -- reads one
literal (a number, string, or `[ ]`/`{ }`/`#{ }`/keyword literal) and
defines a word that always pushes it, never consuming anything:

    scratchpad> CONSTANT: octave 12
    scratchpad> octave octave + .
    24

A constant is really just sugar -- `: name ( -- value ) value ;`
already means the same thing (early binding already makes a plain
colon word behave exactly like a constant), `CONSTANT:` is only
shorter.


10. Saving your work
------------------------

A fresh session starts with nothing but the built-in vocabularies every
time -- anything you `:`/`::`/`VARIABLE:`/`CONSTANT:`/`USE:` at the
REPL only lives in that one session. `save-vocabs!` writes it out as
real, re-executable musics.lang source text (no separate file format
at all); `load-vocabs!` replays it back in:

    scratchpad> VARIABLE: hits 3 hits !
    scratchpad> :: double ( x -- y ) x 2 * ;
    scratchpad> "/tmp/my-session.mlv" save-vocabs!

That file now reads:

    IN: scratchpad
    :: double ( x -- y ) x 2 * ;
    VARIABLE: hits
    3 hits !
    IN: scratchpad

In a fresh session, `load-vocabs!` puts both back -- `hits` at its
saved value of 3, not the `nil` it starts at:

    scratchpad> "/tmp/my-session.mlv" load-vocabs!
    scratchpad> hits @ 21 double .s
    3 42

Two things it deliberately doesn't capture: `FROM:`/`RENAME:`/
`EXCLUDE:`/`QUALIFIED:`/`QUALIFIED-WITH:` wiring (rarer than plain
`USE:`), and words replay in a fixed alphabetical order, not the order
you actually typed them -- if one of your own words calls another,
define the callee under an earlier-sorting name, or reloading may fail
to recompile it.


That's the whole shape of the language as it stands: stack, quotations
+ combinators instead of control-flow syntax, Clojure's own literal
data, named vocabularies (fully implemented, including the
finer-grained imports, transitive `USE:`, and `CLOSE:`/`OPEN:`),
variables and constants backed by real Clojure Vars, a way to save and
reload your own session, and a real way to look up what a word does.
