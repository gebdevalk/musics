Algo cookbook

Composing algo/ generators with algo.tree at the Clojure REPL: trees, their settings, your own algorithms, and live playback.
musics · branch simple-composition · 2026-09-28 · every recipe below was run for real, each starting from seed 2026; results are copied from that run

1. The idea

Two separate things. A tree says what is computed: algorithms nested as ordinary Clojure calls. A tctx holds the settings it runs with: an atom of params, derived from a tree but never holding it.

  • Composition is nesting. (notes (gate euclid (cycled scale))): each algo takes its children and returns a node. A bare algo name is a leaf, euclid = (euclid).
  • Algorithms describe themselves. Each carries :algo metadata: what its children must be (:in), what it makes (:out), and a spec per param: type, range, default. Nothing else about the function changes.
  • Wrong shapes fail when built. The child count and types are checked the moment you write the expression, not while it plays.
  • Params come by name, not by position. Each param is a key in the tctx. Change it with set-param! (or a plain swap!); a validator checks every value against its spec.
  • A name makes it live. (t/live! :riff tree ctx) plays the tree endlessly; every later change to the tctx is heard on the next note, and the GUI's Wall window draws a slider for each ranged param.

At lein repl, algo.tree is t and every ready-made algo is referred. Elsewhere: (require '[algo.tree :as t :refer [defalgo]] '[algo.tree.lib :refer :all]).

5. Writing an algorithm

Give an ordinary defn an :algo attr-map, then (t/expose ns/the-fn) defines its constructor under the short name. For a new function, defalgo does both (the raw fn stays callable as name*).

(defn density-grid "Binary onset grid ..." {:algo {:short :density :in [:weights] :out :grid :params {:density {:type :double :min 0.0 :max 1.0 :default 0.5 :doc "fraction of pulses kept"}}}} [ranks density] ...)the leading args named in :in are children; every later arg is a param, named by the arg itself
  • :params: per param a :type (:int :double :ratio :string :keyword :vector :map :fn :bool :any), a :default, and for a number :min/:max. ##-Inf/##Inf leave a range end open; a ##NaN default makes the param required. :choices limits a string or keyword. Registration refuses an incomplete spec.
  • One value per call? :repeat :len calls the fn :len times (a sampler: normal); :pull {:via :value} calls it once for a generator and pulls :len values (a closure: walk, logistic). No wrapper fn needed; :len is a param like any other.
  • Children not first? :children [:coll] names the args that are children.
  • Keyword args (& {:keys [rotation] :or {rotation 0}}) are params too, their :or the default. A multi-arity fn names the arity to wrap with :arity.
  • Keys: a param keeps its bare name unless two different algos in one tree read it with different specs; then each becomes :short.name (recipe 40). A named instance's are :as/name.

8. Limits worth knowing

  • Generated notes carry pitch and duration only. Dynamics and articulation come from the context (!mf …) once the notes are committed as text.
  • notes->mus covers MIDI 24–119 (octaves 1–8) and throws outside that range.
  • An infinite tree (cycled, shuffled without a head or a finite gate) is fine live, but t/play! and printing need a finite result.
  • All random algos share one RNG (algo.random.core/default-rng). (algo.random.core/seed! 2026) makes a recipe reproducible, but reseeds every live voice too.
  • A defalgo lives in the namespace that defines it: re-run it (keep it in a source file) in a fresh session. A tctx is live state, not saved by persist-session.
  • Keys are checked per tree: two separate trees that happen to share a param name share it only if they share a tctx.
