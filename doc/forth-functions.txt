musics.clj <-> Forth word table
================================
Every public var in musics.clj (59, confirmed 1:1 against (ns-publics
'musics)) has a corresponding Forth word in src/input/forth.clj's
musics-prims, callable from the hosted Forth interpreter
(input.forth) alongside mu! (musics.clj's own nested Clojure REPL).
Both ultimately call the exact same musics.clj functions -- this table
is the same information from two different calling conventions, not
two different implementations. See CLAUDE.md and doc/startup.md for
the fuller mu! writeup, and forth.clj's own "musics.clj bridge" comment
block (above musics-prims) for the authoritative argument-marshaling
conventions below.

Conventions used in the Forth stack-effect column:
  ( before -- after )   before = popped, left-to-right, top of stack
                         rightmost; after = pushed, in order
  id/sid/key/phase/action-id/tx-target args are coerced string->keyword
  automatically (->kw) -- push a string (e.g. via S" verse"), not a
  keyword literal (this Forth has no keyword-literal syntax at all).
  tx is always required explicitly on the Forth side, even where
  musics.clj's own fn defaults it -- push (latest-tx) yourself for that.

Bare musics text ({...}/<<...>>/'{...}/[...]/^{...}/@[...]/@{...}, no
quoting) calls musics.clj/parse directly the moment it's tokenized --
same real core.repo staging PARSE gives you from a quoted S" ..."
string, just no PARSE call needed for that one case.
