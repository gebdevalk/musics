musics.clj <-> Forth word table
================================
musics-prims (src/input/forth.clj) is a fixed, hand-written list of
def-prim calls -- NOT a live (ns-publics 'musics) introspection -- so
it only covers whatever was wired in by hand. It was once confirmed
1:1 against musics.clj's full public API (59 vars, as of 2026-08-13);
since then musics.clj has grown (play!/p!, times/transpose/invert/
scale/reverse/shuffle/thread/active-key/tonal-transpose/tonal-invert/
snap-to-scale/tonal-harmonize) and each new addition has needed its
own manual wiring here to keep up -- don't assume this table (or
musics-prims itself) is exhaustive without checking (ns-publics
'musics) against it directly. Every word here IS callable from the
hosted Forth interpreter (input.forth) alongside mu! (musics.clj's
own nested Clojure REPL); both ultimately call the exact same
musics.clj functions -- this table is the same information from two
different calling conventions, not two different implementations.
See CLAUDE.md and doc/startup.md for the fuller mu! writeup, and
forth.clj's own "musics.clj bridge" comment block (above musics-prims)
for the authoritative argument-marshaling conventions below.

Conventions used in the Forth stack-effect column:
  ( before -- after )   before = popped, left-to-right, top of stack
                         rightmost; after = pushed, in order
  id/sid/key/phase/action-id/tx-target args are coerced string->keyword
  automatically (->kw) -- push a string (e.g. via S" verse"), not a
  keyword literal (this Forth has no keyword-literal syntax at all).
  tx is always required explicitly on the Forth side, even where
  musics.clj's own fn defaults it -- push (latest-tx) yourself for that.

Bare musics text ([...]/#{...}/'[...]/{...}, no quoting) calls
musics.clj/parse directly the moment it's tokenized --
same real core.repo staging PARSE gives you from a quoted S" ..."
string, just no PARSE call needed for that one case.

--------------------------------------------------------------------------------

(parse text)                        PARSE                ( str -- {:sid :ids} )
(s! text)                           S!                   ( str -- {:sid :ids} )
(sc! text)                          SC!                  ( str -- tx )
(try-parse text)                    TRY-PARSE             ( str -- raw-tree )
(parse-file path)                   PARSE-FILE            ( path -- {:sid :ids} )
(:sid m)                            >SID                  ( {:sid :ids} -- sid )
(:ids m)                            >IDS                  ( {:sid :ids} -- ids )

-- commit / abort / pending --
(commit! sid)                       COMMIT!               ( sid -- tx )
(c! sid)                            C!                    ( sid -- tx )
(abort! sid)                        ABORT!                ( sid -- )
(pending sid)                       PENDING               ( sid -- {id node} )

-- registry / navigation / inspection --
(find id tx)                        FIND                  ( id tx -- node )
(ids tx)                            IDS                   ( tx -- ids )
(root-children tx)                  ROOT-CHILDREN         ( tx -- ids )
(children id tx)                    CHILDREN              ( id tx -- children )
(leaves id tx)                      LEAVES                ( id tx -- leaves )
(sq id tx)                          SQ                    ( id tx -- seq )

-- generative transforms -- input phase vs. read-eval-play, kept
-- deliberately separate (see musics.clj's own comment above times for
-- the full reasoning): SQ and ACTIVE-KEY are the only two words here
-- that read core.repo/tx at all. Every word below them takes and
-- returns MATERIAL -- a real, already-built seq, left on the stack by
-- SQ or another of these words' own output -- never a bare id, never
-- a tx. Result pipes straight into PLAY -- play/engine.play already
-- handle a sequential arg directly.
--
-- Single transform: own scalar arg, then material --
--   2 S" verse" LATEST-TX SQ TIMES PLAY
--
-- Chaining more than one: EVERY word's own scalar arg has to be
-- pushed before material is built, in the order the words themselves
-- will later run in (confirmed live, not just reasoned through -- see
-- forth.clj's own comment above this block for the mistake that
-- caught) --
--   7 2 S" verse" LATEST-TX SQ TIMES TRANSPOSE PLAY
(times n material)                  TIMES                 ( n material -- seq )
(transpose n material)              TRANSPOSE             ( n material -- seq )
(invert axis material)              INVERT                ( axis material -- seq )
(invert material)                   INVERT-MEAN           ( material -- seq )
                                                           each part mirrored
                                                           around its OWN mean
(scale n material)                  SCALE                 ( n material -- seq )
(reverse material)                  REVERSE               ( material -- seq )
(shuffle material)                  SHUFFLE               ( material -- seq )
(thread f material)                 THREAD                ( f material -- seq )
                                                           f: an execution token
                                                           (' NAME) or a real fn
                                                           seeded onto the stack,
                                                           same as REGISTER-ACTION!
(active-key id tx)                  ACTIVE-KEY            ( id tx -- key )
                                                           input-phase, like SQ --
                                                           the one place ks comes
                                                           from for tonal-* below
(tonal-transpose ks n material)     TONAL-TRANSPOSE       ( ks n material -- seq )
(tonal-invert ks axis material)     TONAL-INVERT          ( ks axis material -- seq )
(snap-to-scale ks material)         SNAP-TO-SCALE         ( ks material -- seq )
(tonal-harmonize ks n material)     TONAL-HARMONIZE       ( ks n material -- seq )
                                                           ks always explicit --
                                                           (active-key id tx)
                                                           gets one from core.repo;
                                                           no way to build a Key
                                                           from bare Forth text
                                                           directly

                                                           selector vector -- no Forth

(describe id tx)                    DESCRIBE              ( id tx -- map )

(latest-tx)                         LATEST-TX             ( -- tx )
(history id)                        HISTORY               ( id -- [[tx node] ...] )

-- MIDI / playback --
(connect)                           CONNECT               ( -- )

(disconnect)                        DISCONNECT            ( -- )
(play id)                           PLAY                  ( id -- )
                                                           pops whatever's on top and
                                                           forwards it to m/play as-is
                                                           -- a bare id, or a seq left
                                                           by SQ/TIMES/etc. (see
                                                           "generative transforms"
                                                           below), both work; there's
                                                           just no vector/set-literal
                                                           syntax in this Forth to
                                                           write play's own literal
                                                           []/#{} mini-language
                                                           directly from bare text.
                                                           A genuinely :PAR container's
                                                           SQ result plays back in
                                                           parallel correctly -- SQ
                                                           tags it {:parallel? true}
                                                           via seq metadata (there's
                                                           no data-level place left
                                                           for the tag once it's a
                                                           bare seq), and PLAY/DISPLAY
                                                           both consult that metadata,
                                                           not just a literal leading
                                                           :par/:seq keyword.
(play-file! path)                   PLAY-FILE!            ( path -- )
(display id)                        DISPLAY               ( id -- steps )
(stop!)                             STOP!                 ( -- )
(pause!)                            PAUSE!                ( -- )
(resume!)                           RESUME!               ( -- )
(all-notes-off)                     ALL-NOTES-OFF         ( -- )
(play-tx! tx)                       PLAY-TX!              ( tx -- )
(play-latest!)                      PLAY-LATEST!          ( -- )
-- composite, no 1:1 Clojure fn --  PLAY!                 ( str-or-staged -- )
                                                           parse (if needed) +
(parse text) (commit! sid)                               commit! + play-latest! +
(play-latest!) (apply play ids)                            (apply play ids), one step.
                                                           Predates musics.clj/play!
                                                           and isn't rewired to call
                                                           it -- see P! below for
                                                           play!'s own real word.
(p! text)                           P!                    ( str -- )
                                                           short for play! (same
                                                           relationship s! has to
                                                           parse). String only --
                                                           unlike PLAY!, can't accept
                                                           an already-staged
                                                           {:sid :ids} map, since
                                                           p!/play! call m/parse
                                                           themselves.
                                                           Only pops ONE stack value --
                                                           [a:..] [b:..] PLAY! commits
                                                           only the top one; for several
                                                           parts together use one string,
                                                           S" [a:..] [b:..]" PLAY!
