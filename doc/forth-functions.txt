musics.core <-> Forth word table
=================================
musics-prims (src/input/forth.clj) is a fixed, hand-written list of
def-prim calls -- NOT a live (ns-publics 'musics.core) introspection --
so it only covers whatever was wired in by hand. `(count (ns-publics
'musics.core))` currently reports 101 -- don't assume this table (or
musics-prims itself) is exhaustive without checking (ns-publics
'musics.core) against it directly, the same live-truth check this file
has always pointed readers at rather than trying to stay perfectly
in sync by hand. Every word here IS callable from the
hosted Forth interpreter (input.forth) alongside mu! (musics.core's
own nested Clojure REPL); both ultimately call the exact same
musics.core functions -- this table is the same information from two
different calling conventions, not two different implementations.
See CLAUDE.md and doc/startup.md for the fuller mu! writeup, and
forth.clj's own "musics.core bridge" comment block (above musics-prims)
for the authoritative argument-marshaling conventions below.

Conventions used in the Forth stack-effect column:
  ( before -- after )   before = popped, left-to-right, top of stack
                         rightmost; after = pushed, in order
  id/key/phase/action-id args are coerced string->keyword automatically
  (->kw) -- push a string (e.g. via S" verse"), not a keyword literal
  (this Forth has no keyword-literal syntax at all).

Bare musics text ([...]/#{...}/'[...]/{...}, no quoting) calls
musics.core/parse directly the moment it's tokenized --
same real core.repo commit PARSE gives you from a quoted S" ..."
string, just no PARSE call needed for that one case.

--------------------------------------------------------------------------------

(:ids m)                            >IDS                  ( {:ids ids} -- ids )

-- generative transforms -- input phase vs. read-eval-play, kept
-- deliberately separate (see musics.core's own comment above times for
-- the full reasoning): SQ and ACTIVE-KEY are the only two words here
-- that reach into core.repo at all. Every word below them takes and
-- returns MATERIAL -- a real, already-built seq, left on the stack by
-- SQ or another of these words' own output -- never a bare id. Result
-- pipes straight into PLAY -- play/engine.play already handle a
-- sequential arg directly.
--
-- Single transform: own scalar arg, then material --
--   2 S" verse" SQ TIMES PLAY
--
-- Chaining more than one: EVERY word's own scalar arg has to be
-- pushed before material is built, in the order the words themselves
-- will later run in (confirmed live, not just reasoned through -- see
-- forth.clj's own comment above this block for the mistake that
-- caught) --
--   7 2 S" verse" SQ TIMES TRANSPOSE PLAY

(transpose n material)              TRANSPOSE             ( n material -- seq )
(invert axis material)              INVERT                ( axis material -- seq )
(invert material)                   INVERT-MEAN           ( material -- seq )
                                                           each part mirrored
                                                           around its OWN mean
(scale n material)                  SCALE                 ( n material -- seq )
(reverse material)                  REVERSE               ( material -- seq )
(shuffle material)                  SHUFFLE               ( material -- seq )

                                                           (' NAME) or a real fn
                                                           seeded onto the stack,
                                                           same as REGISTER-ACTION!

                                                           from for tonal-* below

(snap-to-scale ks material)         SNAP-TO-SCALE         ( ks material -- seq )

(play id)                           PLAY                  ( id -- )
                                                           pops whatever's on top and
                                                           forwards it to m/play as-is
                                                           -- a bare id, or a seq left
                                                           by SQ/TIMES/etc. (see
                                                           "generative transforms"
                                                           below), both work; there's
                                                           just no vector/set-literal
                                                           syntax in this Forth to
                                                           write play's own literal
                                                           []/#{} mini-language
                                                           directly from bare text.
                                                           A genuinely :PAR container's
                                                           SQ result plays back in

                                                           tags it {:parallel? true}

                                                           no data-level place left

                                                           both consult that metadata,
                                                           not just a literal leading
                                                           :par/:seq keyword.

                                                           short for play! (same

-- wall (per-voice playback algorithms) --
(register-factory! name f)          REGISTER-FACTORY!     ( name f -- )
                                                           f must already be a real
                                                           Clojure fn seeded onto the
                                                           stack from outside -- a
                                                           factory's own fn value
                                                           isn't buildable from bare
                                                           Forth text. f is ALWAYS
                                                           (fn [name params] -> name),
                                                           params ALWAYS a plain map --
                                                           every algo is a factory,
                                                           even a parameterless one,
                                                           so there's no :kind to
                                                           declare
(register-factory! name f doc)      REGISTER-FACTORY-DOC! ( name f doc -- )
(unregister-factory! name)          UNREGISTER-FACTORY!   ( name -- )
(factories)                         FACTORIES             ( -- )              prints
(factories name)                    FACTORIES?            ( str -- )          prints
(unregister-algo! name)             UNREGISTER-ALGO!      ( name -- )
                                                           forgets name's parked
                                                           COOKED algo (*algo-
                                                           registry*), not the
                                                           factory that built it
(assign-algo! path name)            ASSIGN-ALGO!          ( path name -- )
                                                           PREPARES path for its
                                                           NEXT mint only -- never
                                                           reaches an already-live
                                                           voice; a voice's own
                                                           algorithm is immutable
                                                           once minted
(algo-assignments)                  ALGO-ASSIGNMENTS      ( -- )              prints
                                                           the PREPARED table
                                                           (path -> name), not what
                                                           any live voice is
                                                           currently running
(build! name factory-name params)   BUILD!                ( name factory-name
                                                             params -- name )
                                                           params is a plain Clojure
                                                           map (built on the Forth
                                                           side as an aggregate,
                                                           same idiom PLAY! uses
                                                           for its own {:ids ids}
                                                           map) -- every factory
                                                           takes ONE params map --
                                                           applies factory-name's
                                                           registered factory with
                                                           (name params), storing
                                                           the result under name
                                                           (also stamping :factory-
                                                           name/:params onto that
                                                           entry); calling BUILD!
                                                           again with the SAME name
                                                           hot-swaps every voice
                                                           already pointing at it
(build-algo! name f)                BUILD-ALGO!           ( name f -- name )
                                                           the direct, low-level
                                                           counterpart -- f already
                                                           a concrete resolved wall
                                                           fn, no factory involved
